Author’s introduction

bvPVLV.proj (bivalent, Primary Value, Learned Value) is a biologically informed and constrained model of the phasic dopamine signaling system. Relative to earlier versions (\cite{OReillyFrankHazyEtAl07,HazyFrankOReilly10}) the biggest change has been the incorporation of primary aversive outcomes into the framework (e.g., tail shocks, etc). In addition, both the LV and PV learning systems have been considerably expanded, the former as a more detailed model of the amygdala that includes the basolateral amygdalar complex (BLA), and the latter by incorporating the lateral habenula (LHb) as a final common pathway for generating phasic pauses (negative dopamine signals). Also, the terms "LV" and "PV" have been de-emphasized, replaced by the basic distinction between an amygdala-anchored subsystem for handling the generation of positive phasic dopamine signals (i.e., "bursting"), and a ventral striatum-lateral habenula subsystem for handling the generation of negative phasic dopamine signals ("pausing", "dipping").

This project is currently restricted to the learning of Pavlovian contingencies (CS-US pairings) and enables the exploration of several iconic empirical phenomena associated with Pavlovian (classical) conditioning including: appetitive conditioning (positive acquisition; pos_acq); extinction (pos_ext); conditioned inhibition (pos_cond_inhib); and, blocking (pos_blocking). Aversive versions of all of these phenomena are also available (neg_acq, and so on). In addition, the project as been designed to be extendable so that users can develop their own simulations using a table-based specification that leverages a pre-defined input-coding scheme for potential CSs (e.g., A, B, C, ...) and USs (water, food, US3, US4, ...). Basic instructions for creating a new simulation based on copying and modifying an existing parameter table will be provided as a final section to this introduction.

Finally, this project does not encompass learning about instrumental contingencies (action-outcome pairings). Users desirous of exploring the latter would typically start with a variant of a PBWM-based model, or similar, and use the Emergent wizard to add a PVLV module (or replace an older version). Basic instructions for using the LeabraWizard for adding or updating a PBWM/PVLV module to a model are available here: [[1]]


Using bvPVLV.proj

bvPVLV.proj follows the LeabraFlex design which utilizes an ``inside-out?? and ``real-time?? frame of reference that keeps the processing of the current time step (i.e., an AlphaTrial, formerly LeabraTrial) in the foreground at all times, relegating the high-level organization of the environment to be presented to the network to a ``just-in-time?? mode of processing. In a nutshell, it builds upcoming AlphaTrials as needed instead of creating an entire training run's block of trials in the beginning as had been the case with the earlier top-down LeabraTrain, LeabraEpoch, LeabraTrial, LeabraSettle, LeabraCycle mode of organization. While it can be hard to get used to this ``inside-out?? organization at first, once one does it becomes intuitive and, ultimately, provides greater flexibility to the modeler.

Two project-specific programs provide most of the specific implementation of bvPVLV: 1) bvPVLVTask(), which iterates over sequential AlphaTrials, managing the ongoing presentation of inputs to the network and the network?s response to that, under the control of a while-loop until some predefined end point is reached; and, 2) bvPVLVEnv(), which is called by bvPVLVTask() early in each iteration. bvPVLVEnv() sets up the next set of environmental inputs, handling all of the contextualization involved in organizing the various types of trials and the order in which they are presented to the network. We will walk through each of these two key programs below. Most of the other programs in the project can be thought of as a kind of basic infrastructure provided by the general LeabraFlex framework for handling all of the stuff that is not specific to this particular project.

The bvPVLVTask program is basically running all the time iterating from the time it is initially called by a bvPVLVRun() program that is itself iteratively called within a while-loop in the MasterTrain() program managing a full training run. Once called for each iteration, bvPVLVTask() processes each line sequentially from top to bottom. Figure 1 at the right lists the complete program code for the bvPVLVTask program. Some readers may prefer to open the program and follow along that way.

Starting with the green comment line `'// === Start Alpha-Level Trial:

  • The first two commands perform some basic housekeeping on the network
  • bvPVLVTask() calls the bvPVLVEnv program to set up the environment for the upcoming AlphaTrial. bvPVLVEnv() handles everything necessary to set up the next set of inputs to the network (but does not actually present them)
  • Then, if the next AlphaTrial is designated as a TEST trial a flag on the network is set accordingly; else, the flag is kept/set to the default case TRAIN
  • The next active command (after // === Run Minus Phase) then applies (clamps) any and all inputs as designated by the current row in the StdInputData table to the corresponding layers in the network
  • SettleMinus() then runs the entire network under the influence of the clamped inputs for 75 cycles (3 quarters X 25 cycles each)
  • Minus-phase appropriate stats are then computed and recorded
  • The appropriate inputs are again applied, this time including any primary rewards/punishments (USs) if those are available on this AlphaTrial
  • SettlePlus() runs the network again until the plus-phase endpoint (25 more cycles in this case; 100 cycles total for each AlphaTrial). NOTE: 25 cycles is plenty of time to allow for full settling of the network.
  • Plus-phase and trial end stats are then computed and recorded and trial-end housekeeping is performed on the network in preparation for the next iteration through the bvPVLVTask program. NOTE: An additional program for bvPVLV project-specific stats, bvPVLVMiscMonitor(), is called periodically by the bvPVLVRun() program after certain AlphaTrials.


As those familiar with basic computer programming will hopefully agree, the bvPVLVTask program is relatively straightforward and fairly human-readable. With just a little practice we hope it to be reasonably user-friendly. As a result, much of the complexity involved in the bvPVLV project as a whole has been incorporated into the bvPVLVEnv program.

In keeping with the inside-out organization of the LeabraFlex framework, the bvPVLVEnv program ``fetches'? the next AlphaTrial for the calling bvPVLVTask program on an as needed basis. Thus, bvPVLVEnv() starts from the assumption that there is a next trial ready to be fetched and goes and looks for it. Only if it finds that no such trial is available does it then proceed to set up a new sequence of logically-related AlphaTrials, created according to criteria defined in a table containing the defining parameters for the paradigm being explored. This is best illustrated by considering what happens the first time the bvPVLVEnv program is called by bvPVLVTask(), i.e., on the very first AlphaTrial. When called by bvPVLVTask(), executes its master function, PrepCurAlphTrial(). Figure 2 at the right shows bvPVLVEnv()'s starkly simple program code, along with a listing of the nine (9) functions it uses to do its job. Roughly speaking, the functions are used from the bottom-up and are, collectively, a partially nested hierarchy.   • PrepCurAlphTrial() first goes to the StdInputData table (input_data) and increments the read_idx in the table pointing to the next row to be used.
  • The if-else block that follows starting with the next line tests whether that incremented read_idx is still in-range and, if it is returns control to bvPVLVTask() in the else() statement since the StdInputData table is all ready to be read out.
  • However, as we're considering the very first AlphaTrial (i.e., IsEpochStart() evaluates as true) StdInputData is empty and has to be populated, which is done by calling another function SetStdInputData().
  • SetStdInputData() creates a new sequence to AlphaTrials, in this case the very first such sequence, after which the read_idx is pointed to the first row and control returned to bvPVLVTask()
